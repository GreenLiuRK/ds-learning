# 查找

## 一、查找的基本概念

- **平均查找长度 ASL**：所有查找过程中比较次数的平均值，衡量查找算法优劣的核心指标
- **ASL = Σ(pi × ci)**，pi 是查找概率，ci 是比较次数

## 二、顺序查找

从头到尾逐个比较。

- 成功 ASL（等概率）：**(n+1)/2**
- 失败 ASL：n
- 时间复杂度 O(n)
- 优点：对表结构无要求，顺序/链式都行

## 三、折半查找（二分）

**前提：有序 + 顺序存储**（链表不行，因为不能随机访问）。

```c
int BinarySearch(int a[], int n, int key) {
    int low = 0, high = n - 1, mid;
    while (low <= high) {
        mid = (low + high) / 2;
        if (a[mid] == key)      return mid;
        else if (a[mid] < key)  low = mid + 1;
        else                    high = mid - 1;
    }
    return -1;
}
```

- 时间复杂度 **O(log n)**
- 判定树是一棵**平衡二叉树**，高度 ⌊log₂n⌋+1
- 成功 ASL ≈ log₂(n+1) - 1

> `mid = (low + high) / 2` 在 low+high 溢出时出错，工程上写 `low + (high - low) / 2`。

## 四、分块查找（索引顺序查找）

把表分成若干块，块内无序、块间有序，建索引表。

- 平均 ASL = 索引查找 + 块内查找
- 最佳块长：**√n**

## 五、二叉排序树（BST）

- 查找、插入、删除平均 O(log n)
- **最坏 O(n)**：插入序列有序时退化成链表
- 删除两个孩子结点：用中序后继（或前驱）替代

## 六、平衡二叉树（AVL）

- 左右子树高度差 ≤ 1
- 插入后失衡要旋转：**LL、RR、LR、RL** 四种
- 查找/插入/删除都是 O(log n)
- 平衡的目的：防止 BST 退化

## 七、B 树与 B+ 树

| | B 树 | B+ 树 |
| --- | --- | --- |
| 数据存放 | 所有结点都存数据 | 只有叶子存数据 |
| 叶子链表 | 无 | **有**，支持范围查询 |
| 查找 | 可能在内部结点结束 | **必须走到叶子** |
| 应用 | 文件索引 | **数据库索引（MySQL InnoDB）** |

m 阶 B 树的性质：
- 每个结点最多 m 棵子树
- 除根外，每个结点至少 ⌈m/2⌉ 棵子树
- 有 k 棵子树的结点有 k-1 个关键字

## 八、哈希表（散列表）

**用关键字直接算出存储地址**，理想情况 O(1)。

### 常用哈希函数

- 除留余数法：`H(key) = key % p`（p 取小于表长的最大质数）
- 直接定址法：`H(key) = a*key + b`
- 数字分析法、平方取中法、折叠法

### 冲突处理

| 方法 | 说明 | 缺点 |
| --- | --- | --- |
| **开放定址——线性探测** | 冲突就往后找 | 容易**堆积** |
| 开放定址——平方探测 | ±1²、±2²… | 可能探测不到所有位置 |
| 链地址法（拉链） | 同一位置挂链表 | 需要额外指针空间 |

### 装填因子

**α = 表中记录数 / 表长**

α 越大，冲突越多，查找越慢。一般控制在 **0.7～0.8** 以下，超过就扩容。

## 九、易错点

1. 折半查找**只能用于顺序存储的有序表**，链表不行；
2. ASL 要区分"成功"和"失败"；
3. BST 最坏是 O(n)，不是 O(log n)；
4. 哈希表的查找时间与**装填因子**有关，不是纯 O(1)；
5. B+ 树的所有数据都在叶子，且叶子间有链表。

## 十、经典题

| 题目 | 思路 |
| --- | --- |
| 二分查找 | 注意边界 `low <= high` |
| 搜索旋转排序数组 | 二分变体，判断哪半有序 |
| 找出重复的数 | 哈希 / 快慢指针 |
| 两数之和 | 哈希表 O(n) |
| 最长连续序列 | 哈希集合 |
